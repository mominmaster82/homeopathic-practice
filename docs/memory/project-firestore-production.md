Homeopathy অ্যাপের লাইভ ডেটা Production Firestore-এ; `counters/main` থেকে `nextId(field)` নতুন numeric ID বানায় (patients, remedies, rubrics, cases, prescriptions)। Counter বর্তমান max ID-এর চেয়ে কম হলে নতুন লেখা পুরোনো ডকুমেন্ট overwrite করতে পারে; বেশি হলে ID শুধু skip হয়।

**টেস্ট-এন্ট্রি ও ক্লিনআপ নিয়ম (২০২৬-১০-১৭-এ দুই দফায় যাচাই):**
- Production ফ্লো টেস্টে স্পষ্ট নাম ব্যবহার করুন — যেমন `Zztest ...` ওষুধ এবং `ZZ Test` সেকশনের রুব্রিক।
- টেস্ট শেষে UI দিয়ে টেস্ট ওষুধ/রুব্রিক মুছুন (custom-only; সংশ্লিষ্ট লিংকও মুছে যায়), তারপর Firestore read-only যাচাই করুন: টেস্ট ডকুমেন্ট/লিংক বা orphan নেই।
- এরপর `counters/main`-এর প্রতিটি field = সেই collection-এর **max numeric ID** (ডকুমেন্ট সংখ্যা নয় — ID-তে ফাঁক থাকায় count দিলে collision হবে)। ২০২৬-১০-১৭-এ remedies 535→534, rubrics 1132→1131; patients 3, cases 6, prescriptions 9 অপরিবর্তিত ছিল।
- টেস্ট ডকুমেন্ট থাকা অবস্থায় counter কমানো যাবে না; আগে ডিলিট নিশ্চিত করুন।
- ২০২৬-১০-১৭ ক্লিনআপের পর baseline: 166 remedies, 546 rubrics, 3019 rubric_links, 0 orphan; remedies id 367–534, rubrics id 586–1131; একমাত্র custom rubric id 737 (Head, বৈধ — টেস্ট নয়)।
- ২০২৬-১০-২৩ (ধাপ ৪ সিঙ্কের পর) baseline: 166 remedies, 606 rubrics, 3271 rubric_links; counter `rubrics` = 1191। নতুন ৬০ রুব্রিক id 1132–1191, ২৩২ লিংক; ১টি custom rubric অক্ষত। লোকাল SQLite: 605 rubrics, 3248 links।
- ২০২৬-১০-২৪ (ধাপ ৫ clinical সমৃদ্ধিকরণ): ৩৯টি ওষুধের `clinical` লোকাল ও প্রোডাকশনে আপডেট; Firestore গণনা অপরিবর্তিত (166 remedies, 606 rubrics, 3271 links)। ৭টি drift-ফিল্ড সুরক্ষিত ছিল — Arnica keynotes; Aurum clinical/keynotes; Eupatorium clinical; Sanguinaria clinical/better/worse। `db/remedy-baseline.json`-এ সমৃদ্ধিকরণের **আগের** মান সংরক্ষিত; এই baseline ফাইল data.js থেকে পুনরায় বানাবেন না, নইলে drift সুরক্ষা নষ্ট হবে।
- ২০২৬-১০-২৫: **Role-based rules live** — `users` কালেকশনে একমাত্র ডকুমেন্ট অ্যাপ মালিকের (`role: super_admin`, `status: active`); Auth ইউজারও একমাত্র তিনিই। Active subscriber শুধু রেফারেন্স (remedies/rubrics/rubric_links/settings) পড়তে পারে; রুব্রিক/ওষুধ লেখা, রোগী/কেস/প্রেসক্রিপশন, counters ও users list — denied। super_admin সব পারে; অজানা কালেকশন ডিফল্ট বন্ধ। Rule টেস্ট ও UI টেস্টের অস্থায়ী ইউজার/ডকুমেন্ট পরিষ্কার করা হয়েছে। গণনা অপরিবর্তিত: 166 remedies, 606 rubrics, 3271 links।
- ২০২৬-১০-২৬: **সাবস্ক্রিপশন expiry rules live** — subscriber-এর `expires_at` ভবিষ্যৎ Timestamp না হলে reference reads (remedies/rubrics/rubric_links/settings) 403; super_admin bypass। লাইভ REST টেস্ট: future 200 → expired 403 → renew 200। টেস্ট subscriber মুছে ফেলা হয়েছে; এখনো একমাত্র অ্যাডমিন অ্যাকাউন্ট।
- ২০২৬-১০-২৯ (কী-নোট সমৃদ্ধিকরণ, commit `dee1148`): সব ১৬৬ ওষুধের `keynotes` পুনর্লিখিত — শারীরিক বর্ণনার শেষে `। মন: ...` মানসিক অংশ; ০টি বাদ পড়েনি। Clinical সেকশনে ৩৫টি নতুন রোগ (ডেঙ্গু, ম্যালেরিয়া, যক্ষ্মা, বেলস পলসি, গোড়ালি ফাটা ইত্যাদি) ও ১৮১টি গ্রেডেড লিংক। নতুন baseline: 166 remedies, 641 rubrics, 3452 rubric_links; counter `rubrics` = 1226; নতুন রুব্রিক id 1192–1226। Arnica ও Aurum-এর ব্যবহারকারী-সম্পাদিত কী-নোট অক্ষত রেখে `মন:` যোগ; বাকি ৫টি drift-ফিল্ড (Aurum clinical; Eupatorium perf clinical; Sanguinaria clinical/better/worse) ছোঁয়া হয়নি। দ্বিতীয় dry-run-এ ০ পার্থক্য (idempotent)।
- ২০২৬-১০-২৯ (দ্বিতীয় ধাপ, commit `ee29184`): ১৪টি বাদ পড়া অতি-ব্যবহৃত ওষুধ যোগ (id 535–548) — baseline এখন 180 remedies, 676 rubrics, 3914 rubric_links; counter remedies 548, rubrics 1261; নতুন ৩৫টি Mind রুব্রিক id 1227–1261। Clinical-এর সব ১৩৩টি রুব্রিকে এখন ≥৬ লিংক; Mind ৮৭ রুব্রিক, ৫০৪ লিংক। নতুন `server/firebase-sync-new-remedies.mjs` (dry-run ডিফল্ট) নতুন ওষুধ তৈরি করে ও baseline-এ যোগ করে; Firestore-এ আগে ওষুধ তৈরি না করে rubric sync চালালে নতুন ওষুধের লিংক বাদ পড়ে। তিনটি সিঙ্কের দ্বিতীয় dry-run-এ ০ পরিবর্তন।
- ২০২৬-১০-৩০ (তৃতীয় ধাপ, ৩০০ ওষুধ): ১২০টি নতুন ওষুধ id 549–668 ও ৬৪৩টি নতুন লিংক যোগ। Firestore: 300 remedies, 676 rubrics (৬৭৫ সিডেড + ১ কাস্টম), 4,557 rubric_links (৪,৫৩৫ সিডেড + ২২ কাস্টম); counter remedies 668, rubrics 1261; baseline 300 remedies / 675 rubrics / 4,535 links। নতুন ডেটা `server/db/remedies-300.js`-এ, `data.js` শুধু ইমপোর্ট করে। বড় সিঙ্কে free-tier দৈনিক read-quota শেষ হতে পারে — ওই সময়ে rubrics sync মাঝপথে থামলে কিছুই নষ্ট হয় না; কোটা রিসেটের পর একই কমান্ড rerun করলেই বাকি লিংক যোগ হয় (idempotent)।
- ২০২৬-১০-৩০ (চতুর্থ ধাপ, ৫০০ ওষুধ, commit `9f9ced5`): `server/db/remedies-500.js`-এ আরও ২০০টি ওষুধ (id 669–868, প্রতিটিতে ৫টি লিংক) — total 500 remedies / 675 rubrics / 5,535 links। Firestore: 500 remedies, 676 rubrics, 5,557 rubric_links; counters remedies 868, rubrics 1261। দ্বিতীয় dry-run-এ ০ পরিবর্তন (idempotent)। হোস্টিং ডিপ্লয়ের পর লাইভ যাচাই: Streptococcinum প্রোফাইলে কী-নোট/ক্লিনিক্যাল/৫ লিংক, রেপার্টরি সার্চ «হুপিং কাশি»-তে Pertussinum, console ত্রুটি নেই। ওই দিনের real usage counters: patients 3, cases 7, prescriptions 10।
- নতুন ওষুধের লিংক সবসময় **আগে** `firebase-sync-new-remedies.mjs --apply` চালিয়ে ওষুধ তৈরি করুন, তারপর `firebase-sync-rubrics.mjs --apply` — নইলে নাম→ID ম্যাপিং না পেয়ে লিংক বাদ পড়ে।
- Firestore-এর রুব্রিক টেক্সট `data.js`-এর সঙ্গে whitespace-এ ভিন্ন হতে পারে (যেমন `Fear of death ( মৃত্যু ভয় )` বনাম `Fear of death (মৃত্যুভয়)`)। Targeted sync-এ `(section, rubric_text)`-এর সব whitespace বাদ দিয়ে মিলিয়ে শুধু অনুপস্থিত যোগ করুন — নইলে একই রুব্রিক ডুপ্লিকেট হবে।
- `server/firebase-key.json` কখনো কমিট/শেয়ার করবেন না (gitignored)। লিংক সিঙ্কে পুরোনো `firebase-upload.mjs` চালাবেন না — ডুপ্লিকেট করে; targeted/idempotent sync ব্যবহার করুন — বিস্তারিত [[project-homeopathy-app]]।

**Why:** Counter ভুল হলে নতুন ওষুধ/রুব্রিক পুরোনো ID-তে গিয়ে আসল ডেটা overwrite করতে পারে; আর production-এ টেস্ট-ডেটা রয়ে গেলে ব্যবহারকারীর আসল ডেটার সঙ্গে মিশে যায়।

**How to apply:** Production টেস্টের পর সর্বদা ডিলিট → Firestore যাচাই → max-ID-তে counter রিসেট → আবার যাচাই করুন। নতুন রুব্রিক/লিংক সিঙ্কে আগে dry-run রিপোর্ট দেখুন, `--apply` শুধু অনুমোদনের পর; দ্বিতীয় dry-run-এ ০ পরিবর্তন হলে idempotent নিশ্চিত। লাইভ UI যাচাইয়ে Search box দিয়ে টার্গেট আইটেম একা করে নিন; লম্বা তালিকায় MCP uid-click পাশের সারিতে লাগতে পারে (২০২৬-১০-১৭-এ ঘটেছে), তাই সন্দেহ হলে Firestore read-only query দিয়ে চূড়ান্ত নিশ্চিত করুন।
